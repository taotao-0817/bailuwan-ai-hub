# Three.js / UE 孪生适配接口（v1.1）

本仓库的可运行三维客户端是 Three.js，没有 UE 源工程。以下是同一业务后端向三维客户端提供状态的接入契约；UE 客户端需按契约实现并单独验收，不能据此视为 UE 功能已完成。

## 职责边界

| 模块 | 权威来源与职责 | 客户端配合 |
| --- | --- | --- |
| 资源接入层：连 | 设备状态、能力、位置、回执；空间和岗位的配置与占用 | 按稳定资源 ID 关联模型节点 |
| 智能中枢：想 | 目标、事件、资源选择、计划、风险门禁与结果 | 展示后端任务状态与选择说明 |
| 三维孪生：看 | 将业务状态映射为空间标记、路径、标签与告警范围 | 只做展示、选中和视角交互，不自行改变任务状态 |
| 管理系统：管 | 受权限约束的发起、审批、确认/拒绝、处置和追溯 | 通过业务 API 操作，再读取最新快照 |

## 读取接口

- 应用默认地址：`http://127.0.0.1:8788`。
- `GET /api/twin/snapshot`：当前登录主体可读取的统一状态快照。
- `GET /api/hub`：资源与中枢任务视图，适合非三维管理客户端。
- `GET /api/events`：SSE 更新通知，收到 `update` 事件后重新读取快照。
- `GET /api/health`：应用版本、模拟模式及模拟器连接状态。

接口使用后端登录会话；浏览器端采用 HttpOnly Cookie。UE 后续应通过正式客户端身份适配接入，当前演示中不得把超级管理员 Cookie 或模拟器令牌硬编码到 UE 包内。`/api/simulator/tick` 是受令牌保护的本机模拟器接口，不是 UE 写状态接口。

快照结构：

```json
{
  "schemaVersion": "1.1",
  "version": "1.1.0",
  "at": "ISO 8601 UTC",
  "coordinateSystem": "local-meters",
  "buildings": [],
  "devices": [],
  "alerts": [],
  "patrols": [],
  "deliveries": [],
  "hub": {
    "resources": [],
    "tasks": [],
    "notifications": []
  },
  "takeover": { "active": false }
}
```

客户端应忽略未知新增字段，以 `schemaVersion` 判断不兼容结构；不要依赖数组顺序或中文名称作为主键。

## ID、空间与状态映射

- 建筑使用 `building.id`；设备使用 `device.id`；通用资源使用 `resource.id`，`sourceId` 指向原业务实体。
- 模型节点映射表应由客户端资产配置维护，例如建筑 `B02` 对应某个 UE Actor，设备 `DEV-018` 对应某个部件；业务后端不保存 UE Actor 指针。
- 本地坐标单位为米，`x/z` 是园区平面，`y` 向上。当前坐标是演示园区局部坐标，不能直接当经纬度或真实 GIS 测量值。
- UE 通常使用厘米，适配器须统一轴向、单位和原点；推荐显式配置变换，不在每个业务案例内写转换。
- `buildingId`、`floor` 是业务归属；设备位置与楼层标签应以快照为准。楼层剖切只改变客户端可见性。
- 设备 `status`、任务 `status/progress`、告警 `status` 分别表达运行事实、业务执行和处置状态，不能混用。

## 更新、重连与显示规则

1. 登录后读取完整快照，建立 `ID → 模型节点` 映射。
2. 订阅 SSE。`update` 只表示“有状态变化”，不是设备命令成功证明；按当前权限重取快照。
3. 合并同一实体的最新数据，使用插值平滑位置，但不得自行推进业务进度或补写完成状态。
4. SSE 断线时显示连接降级，保留最近快照及采样时间；重连后全量刷新。必要时以低频轮询补充。
5. 模拟器离线、命令 `pending`、`failed`、`timed_out` 必须可区分。命令没有成功回执时不可显示设备已执行。
6. 人工接管期间突出操作者与时间，暂停自动化交互；恢复后以新快照重建视图，不重放旧指令。

## 从三维发起交互

建筑、设备、资源、告警或任务的点击应返回稳定业务 ID，由管理界面打开对应详情。需要业务动作时，使用统一业务 API，接受服务端角色校验、风险确认、幂等和状态机检查。

中枢接口：

| 接口 | 用途 | 风险边界 |
| --- | --- | --- |
| `POST /api/hub/plan` | 将目标解析为计划，返回候选、选择理由和步骤 | 规划不等于执行，选择结果在执行前还要重校验 |
| `POST /api/hub/events` | 位置化火情/跌倒模拟事件，形成处置任务 | 高风险动作等待明确人工确认 |
| `POST /api/hub/tasks/:id/action` | 开始、确认、拒绝、暂停、继续、完成或重规划 | 只允许当前角色与任务状态对应的操作 |

高风险确认界面应显示影响位置、资源、步骤和理由，并支持拒绝及填写原因。拒绝不应让客户端自行补出“已恢复”动画。任务结果以关联订单、审批、巡检、告警、预订和设备回执为依据。

## 错误、权限与隐私

标准错误保持 `{error:{code,message,details?},requestId}`。客户端展示可理解的 `message`，记录 `requestId` 便于排查；不能把 HTTP 200、工具调用返回或动画播放结束一律解释为业务成功。

快照必须遵循与管理界面相同的主体访问范围。岗位响应人员是模拟职能代号；会议目标、参与人和通知正文可能含业务信息，不能通过 UE 或 SSE 扩大可见范围。不要在三维客户端保存另一套可写业务状态，也不要绕过后端直接调用设备协议。

## 后续 UE 联调验收

- 同一 `task.id` 在中枢、管理界面和 UE 显示的状态、进度、关联资源一致。
- 替换建筑与设备模型后仅修改映射/坐标配置，五类案例不需要各写一套 UE 业务逻辑。
- 断网、资源忙碌、低电量、设备失败、人工拒绝与接管恢复均能显示真实状态。
- UE 客户端实际连接、认证、数据规模、帧率、空间定位和辅助功能仍须团队现场验证。
