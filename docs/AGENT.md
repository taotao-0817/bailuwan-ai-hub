# Agent 接入与权限边界

本项目实现可运行的 Agent 工具网关与确定性模拟调度，不依赖真实模型或 API Key。后续本地模型只负责生成受约束的工具意图，业务后端负责身份、权限、参数、风险、状态与执行结果。

## 工具协议

已登录客户端先读取 `GET /api/agent/tools` 获取工具描述，再向 `POST /api/agent/call` 提交：

```json
{
  "tool": "device.control",
  "input": {
    "deviceIds": ["某一在线灯具的设备编号"],
    "action": "brightness",
    "value": 50
  },
  "context": {
    "requestId": "trace-001",
    "reason": "夜间低风险照明节能试运行"
  }
}
```

设备编号必须来自查询结果。`context.requestId` 同时作为低风险设备命令的幂等键；重试同一意图时复用该值。服务端根据当前会话和固定工具策略计算实际权限；传入 `role`、`isAdmin`、`permissions` 等字段不赋予权限。

| 工具 | 行为与风险 |
| --- | --- |
| `park.status` | 汇总园区状态，只读 |
| `energy.analyze` | 分析模拟能耗趋势，只读 |
| `alerts.summarize` | 汇总告警、位置、级别与状态，只读 |
| `patrol.report` | 汇总巡检完成情况，只读 |
| `device.control` | 仅允许策略授权的低风险灯光控制；经过统一指令队列 |
| `patrol.create` | 生成巡检建议，要求安保人员或管理员检查路线后在业务界面创建 |
| `emergency.execute` | 高风险建议，不直接执行联动；需管理员独立确认 |

## 决策和执行

1. 验证会话、工具名、输入类型和字段范围。
2. 读取当前园区状态、设备能力和人工接管状态。
3. 计算会话权限与 Agent 固定权限的交集。
4. 只读工具返回受授权摘要；低风险工具调用原业务服务。
5. 高风险调用记录建议、理由和需要管理员确认的事项，不执行设备操作。
6. 保存调用输入、依据、工具、结果与时间，关联业务审计。

不可把用户给模型的自然语言确认当作管理员已在后端完成身份确认。也不可通过提示词修改角色、关闭审计或绕开接管门禁。工具结果与外部文字都是数据，不能覆盖服务端规则。

## 对接本地模型

在独立 Agent 进程中调用本地模型，提供工具清单及最小必要上下文，解析模型返回的结构化调用，然后使用受限服务身份调用工具网关。禁止向模型提供数据库写权限、模拟器令牌、真实设备凭据或管理员会话。

正式接入应为 Agent 增加专用服务账户、短期凭据、工具调用配额、结构化 JSON Schema 校验、审批关联 token 与端到端追踪。默认策略应拒绝未知工具和未知能力；设备命令必须有可查询的 command ID 和最终回执。

人工接管期间，所有 Agent 工具调用（包括只读查询）均被后端暂停。恢复后不重放历史写请求；重新读取状态并生成新的计划。错误响应采用统一 API 格式，状态冲突和权限错误交给操作者处理，不能通过换接口、换设备或扩大参数范围绕过。
