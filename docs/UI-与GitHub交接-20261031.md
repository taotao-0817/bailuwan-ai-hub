## 最简单的 GitHub 接法：GitHub Desktop

目前电脑已有 Git，但项目尚未初始化仓库。本次没有登录 GitHub、创建远程仓库、提交或上传代码。

1. 安装并登录 GitHub Desktop。
2. `File → Add Local Repository`，选择本项目 `bailuwan-ai-hub-v1.1`。不要选外层“白鹭湾”，否则会把图库、素材包和多个版本混到一起。
3. 提示不是 Git 仓库时，点击 `create a repository here`，确认最终目录仍然是现有项目，不要再嵌套生成一个空目录。
4. 在 Changes 检查文件：不能包含 `.env`、`.env.local`、私钥、数据库、`.runtime`、`node_modules` 或 `dist`。当前 `.gitignore` 已补齐常见排除项；`.env.example` 是应该提交的无密钥模板。不要在示例或源码里填写真实密钥。
5. 首次提交建议命名 `baseline: role UI and delivery integration`。**Git 只能从这次提交起记录差异，无法自动还原此前每一次修改**；此前快照可另行保留。
6. 点击 `Publish repository`，选 **Keep this code private**。邀请成员需要仓库拥有者自行确认访问权限。
7. 每次开始工作先 `Fetch origin / Pull`；在 `Current Branch → New Branch` 建功能分支，例如 `ui/twin-home` 或 `feat/robot-adapter`，不要所有人直接改 main。
8. 改完查看 Changes → 写提交说明 → Commit → Push origin → Create Pull Request；由另一人检查后合并 main，再拉取最新代码。

组员已经有 GitHub 仓库时，先 Clone 组员仓库并新建分支，再把本地已审查的改动合入；不要另建两个互不相干的远程仓库，也不要强制推送覆盖对方历史。

当前源码等约1MB，没有GLB/FBX等模型大文件，暂不需要Git LFS。以后3D资源单独采用团队约定的素材存储或Git LFS，并遵守授权；不要把整个图库zip上传源码库。

## GitHub 不等于在线演示

GitHub 保存版本和协作代码，不会自动运行 Node 后端、SQLite、设备模拟器。GitHub Pages 只能托管静态文件，不能直接跑完整系统。组员 Clone 后安装依赖并双击 PREVIEW.cmd 可以在各自电脑预览，演示数据库各自独立。若要多人同时访问同一套数据，另做服务部署，不要把本机带演示密码的服务直接暴露到公网。
